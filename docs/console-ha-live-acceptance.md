## “发送结果尚不确定”排查与修复

用户反馈输入“打开书房灯”后出现不确定提示。原后端把解析校验拒绝统一包装为 `error/control_unavailable`；前端对这类 error 进入历史核对。因此没有创建提议的明确解析拒绝，也会显示发送状态未知。原错误分支没有保留错误分类，不能声称已捕获用户那一次请求的具体失败原因。

在本机相同模型、prompt 和 schema 下，以唯一合成开关重建相关情形：模型将未登记的“书房灯”猜成该开关，现有完整名称/别名校验正确拒绝；输入完整“书房进门开关1”则通过同一校验。[诊断记录](console-ha-switch-name-diagnostic-2026-10-09.json)仅包含合成开关，没有 HA 客户端或真实设备动作，也不是原始现场请求的完整候选抓包。

修复只将 `ErrHAIntentInvalid` 转成正常保存并发送的澄清回复，最多提示3个当前授权候选名称。请求取消优先返回取消错误；目录/模型不可用、存储或发布失败等其他错误不冒充成功。现有实体名称校验、用户身份、单独确认和 HA 执行流程均未放宽。诊断日志仅保存固定错误类别，不输出原始错误或输入。

更新后建议先发 `查询书房进门开关1的状态`，需要操作时发 `打开书房进门开关1` 或 `关闭书房进门开关1`，再核对并点击提议卡确认。“书房灯”仍不是已核验的开关别名，不能据此推断下游灯具。
