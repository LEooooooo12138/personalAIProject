# 人物文档上传、MiMo 与语音对话首版

> 历史文档：设计状态与验证结论仅对应文档日期；本次发布仅脱敏，不代表重新执行验收或完成部署。

创建：2026-10-09。实施修订：2026-10-10；人格分层修订：2026-10-12；TTS 与 VoiceClone 修订：2026-10-13。本文保留用户确认的前端保存入口及 LLM/ASR/TTS 分别支持本地、云端和混用的设计，明确个人管家基础身份与人格文档的职责。本轮用户确认当前使用 MiMo、未来可能切换本地；现有云端配置已保存，暂无克隆参考音频，仍保留上传与配置入口。

## 使用入口

管理员登录 Console 后，在“我的”打开“助手设置”，地址为 `/app/admin/assistant`。页面提供三个独立的模式选项、MiMo API Key 保存/移除与服务区域、MiMo TTS/VoiceClone 模型及内置音色选择、克隆参考音频上传/替换/移除、本地 ASR/TTS 完整服务地址，以及人物 Markdown 上传。普通成员不能修改这些设置。

人物文件需为 UTF-8 `.md`，非空且不超过 256 KiB，固定写入 `<console.data_dir>/personality/default.md`。文件选择与保存分开，保存成功显示更新时间和大小；再次上传替换同一文件。文件名不影响服务器路径。保存后从后续新回复开始自动应用，已有会话也读取最新人格；已保存正文保持不变。无需按人物手工改写文档。

Key 只从密码输入框提交到 Go 后端，不返回原值，不存入浏览器 localStorage/sessionStorage。Windows 下配置与 Key 一起经 DPAPI CurrentUser 加密，原子保存到 `<console.data_dir>/secrets/mimo.dpapi`，目录与文件 ACL 限制为当前运行账号。重启时必须使用相同 Windows 账号；密文文件不能直接搬到其他账号使用。非 Windows 可保存无 Key 配置，保存云端 Key 会明确失败，等待该平台的安全存储适配。

## 个人管家与人格文档

每条普通 Console 对话回复都包含系统提供的个人管家基础身份、职责及操作确认规则。未上传文件时使用默认管家；上传人格文档后，基础身份仍然存在，文档用于补充人物名称、性格、语气与表达习惯，无需重复定义管家。支持“她叫小序，性格温和，说话简洁”等第三人称设定，助手应自然采用这些特点，而非转述或分析人物档案。

系统用固定的最高优先级 `system` 消息定义个人管家身份、职责、能力边界与人格使用规则；原始人格 Markdown 和知识上下文放入随后一条 `user` 角色的后台参考 JSON，分别使用 `personality_markdown` 和 `knowledge_context` 字段，再跟随会话历史和当轮问题。参考资料不是用户的新问题，其中的角色标签、分隔符或覆盖指令均不改变消息角色。无论上传、替换或移除人格，固定 system 指令均不被原始文档替换。人格设定不能替代基础职责、权限和操作确认规则，也不能作为设备状态或执行结果的依据。权限检查、操作确认和设备结果仍由服务端既有流程负责；提示词只是回复行为指引，不是安全权限的强制机制。

只有身份询问和自我介绍需要明确个人管家身份，同时采用人格姓名与语气。能力介绍、情绪回应、建议、异议和相关兴趣沿用人格的关注点和表达节奏，不要求每轮重报身份或按固定目录介绍能力。实际服务范围不被人物爱好或技术弱项缩减。虚构学校、团体、职业不是助手的现实履历；旧会话里的纯角色自称也不能覆盖当前身份。用户明确讨论作品人物时，仍可介绍人物背景并区分虚构角色与当前助手。

普通 Console 本地知识问答及云端/混合直接回复使用完整人格原文。设备表达在事实确定后由本地组件根据人格自动选择阶段语气，事实由程序填入；人格不进入意图分类、设备目标解析、提议决策、控制执行、ASR 输入或 TTS 指令，也不改变内部任务与旧 REST/widget 请求。确认、取消和核对后的正文保存为去重的本地消息，历史、界面和朗读共用正文。云端或混合回复会将人格内容随对话发送到 MiMo。已存在但无效或不可读取的文件仍返回 `personality_unavailable`，提示管理员修复，不静默忽略。

## 模式及隐私边界

| 部分 | 本地 | 云端 | 混用 |
|---|---|---|---|
| LLM | 现有 Ollama 模型 | `mimo-v2.6-flash` | 本地优先，临时故障时一次云端回退 |
| ASR | 本机 OpenAI-compatible 识别服务 | `mimo-v2.5-asr` | 本地优先，临时故障时一次云端回退 |
| TTS | 本机 OpenAI-compatible 合成服务 | 内置音色 `mimo-v2.5-tts`，或参考音频克隆 `mimo-v2.5-tts-voiceclone` | 本地优先，临时故障时一次云端回退至所选 MiMo 模型 |

三个模式默认本地；可以先保存设置、以后再配置 Key 或服务。保存成功表示配置已持久化，不代表供应商连通性或额度已验证。本地模式不会自动访问云端。混用只对未配置的本地语音服务、连接/超时、5xx 等临时故障回退；取消、无效输入、4xx、证书或协议错误不回退。

LLM 模式在新对话首条消息前固定，修改设置只影响新对话。旧对话没有模式记录时按本地处理。云端/混用只使用直接对话链，不附加本地知识库、设备候选目录、设备状态或历史设备结果；云端历史仅包含该模式下的普通对话问答。

选择云端或混用即允许用户主动输入的文本（包括识别文本）发送给 MiMo，也可能先用于不附带任何设备候选的意图分类。普通对话因此不依赖本地设备解析模型。涉及设备时，目标解析、设备目录读取、状态查询、操作提议和确认仍走原有本地流程；本地模型不可用时设备请求明确失败，不把设备上下文转交云端。

ASR 与 TTS 独立于 LLM 模式。例如本地 ASR + 云端 LLM 会让音频留在本机，但识别出的文字发送云端；云端 TTS 会发送要朗读的普通回复。设备回复、包含知识库信息的回复、延续敏感本地历史的回复和未标记的旧回复强制本地朗读。TTS 输入由服务器根据当前用户拥有的已保存消息索引和内容哈希提取，不能由客户端提交任意文本。

内部任务、个人 Vault、嵌入、旧 REST/widget 请求沿用既有本地路由。本次云端入口限定为登录后的 Console 对话。

## 语音交互

聊天页点击开始录音，再点击结束并识别；识别结果作为一次普通消息发送，沿用原来的设备确认卡。录音上限 60 秒，到达上限后等待用户发起识别。单次音频不超过 8 MiB。麦克风需要 HTTPS，或本机 localhost 安全上下文及浏览器权限。

浏览器把录音解码、重采样为单声道 16 kHz PCM16 WAV，服务器验证格式和时长。由录音计时/编码填充造成的少量超出在浏览器裁剪到 60 秒。服务器另外支持可选 FFmpeg 对 WebM/MP4 等做受限管道转换；正常网页流程不依赖安装 FFmpeg。

回复可手动朗读，也可打开默认关闭的“自动朗读”；只自动读新回复，不读恢复的历史。提供停止按钮。切换账号、对话、关闭页面或取消任务会释放麦克风、停止播放器并忽略过期结果。录音/识别过程中避免与文字发送重复提交，保留用户原有草稿。

任务只归属当前账号，每账号最多 1 个活动任务、全局最多 4 个，最多保留 16 个结果；任务期限和结果保留期均为 120 秒。取消工作未真正退出前不释放容量。配置替换会取消已有语音任务，不将同一任务悄悄改为另一种模式。

## MiMo 音色与克隆参考音频

内置音色可选 `mimo_default`、冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean，默认普通 TTS 模型与冰糖音色。切换至 VoiceClone 会保留内置音色选择；切回本地也保留 MiMo 配置和原有本地地址。模型、音色与参考音频分别保存，旧客户端省略新增配置字段时保留已有选择。

参考音频仅接受 WAV 或 MP3，原始文件不超过 6 MiB、60 秒。WAV 必须是有效 PCM16；服务器根据采样数据验证时长。MP3 通过服务器上的 FFmpeg 做受限的本地管道转换，规范化为 PCM16 WAV；没有 FFmpeg 时可直接使用合格 WAV。文件名和上传内容不能指定服务器路径或远端音频 URL。

样本固定保存到 `<console.data_dir>/secrets/tts-reference.dpapi`，采用 Windows DPAPI CurrentUser、受限 ACL 和原子写入。前端仅接收是否存在、大小、更新时间和 revision，不接收样本或密文。上传、替换、移除均校验管理员权限、CSRF 和期望 revision；删除保留加密的空记录与新 revision，旧页面不能覆盖或恢复已删除的样本。非 Windows 未配置安全样本存储时明确失败，不明文落盘。

上传只保存到本机，不调用 MiMo。使用云端克隆朗读时，才将参考 WAV data URL 与本次朗读文字发送到所配置的 MiMo 入口。缺少样本返回 `voice_reference_required`，不静默降级成内置音色；供应商克隆失败也不改用普通 TTS 重试。本地 TTS 不需要克隆样本，不接收 MiMo Key 或样本；混用模式的本地成功也不受缺少样本影响，仅在需要云端克隆回退时要求有效样本。样本或服务设置变化会取消既有语音任务。

## 本地服务接入

本地 LLM 沿用 `inference.endpoint` 与现有 Ollama 模型配置。ASR/TTS 从新页面填写完整 HTTP loopback 地址，使用 `127.0.0.1` 或 `[::1]`，不能填写远端主机、密钥、查询参数或 fragment。例如：

- ASR：`http://127.0.0.1:8000/v1/audio/transcriptions`，multipart `file` 为 WAV，模型别名 `whisper-1`，返回 `{"text":"识别文字"}`。
- TTS：`http://127.0.0.1:8001/v1/audio/speech`，JSON `model: tts-1`、`voice: alloy`、`input`、`response_format: wav`，返回有效 PCM16 WAV。

服务需支持或映射上述模型/音色别名。本次提供适配与选择入口，不自动下载模型、安装本地服务，也未做本地中文音质或延迟测评。

## MiMo 接入依据及方案评价

MiMo 三类请求统一由 Go 根据已保存的 Key 类型和服务区域解析官方 Base URL，再请求 `/chat/completions`。按量付费、Token Plan 中国区、新加坡区和欧洲区使用各自匹配的入口，不能固定到按量付费地址，也不能混用 Key 类型。当前已保存配置使用 Token Plan 中国区；文档不记录 Key。Key 仅放在 `api-key` 请求头，禁止重定向。文本模型使用 `max_completion_tokens`、关闭 thinking；结构化意图使用 JSON object 输出，再通过已有严格字段校验。ASR 为 WAV data URL 输入；TTS 使用 assistant 文本与 WAV 音频输出，普通模型发送内置音色枚举，克隆模型发送参考 WAV data URL。当前不做供应商流式音频。

验收区分真实 Windows DPAPI/ACL 文件操作、模拟供应商 HTTP 合约、任务归属与取消、前端交互、浏览器端到端及真实供应商调用。2026-10-13 已使用现有配置完成一次普通 MiMo TTS 短句生成：返回 107,564 字节音频，请求耗时 1,251 ms；这是单次合成成功证据，不代表音质或并发性能测评。用户暂无参考音频，VoiceClone 的入口、存储和请求合约经过验证，真实克隆音色尚未实测。部署、运行服务和完整验证结果见 [2026-10-13 TTS / VoiceClone 验收记录](2026-10-13-mimo-tts-voiceclone-validation.md)。
