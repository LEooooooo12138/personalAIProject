## 1. 目标与范围

为项目主人和家庭成员提供一个中文、适配手机与电脑的日常入口。家人能够登录、进行知识问答、跨设备恢复自己的会话、查看获准共享的家庭设备和自动化结果。管理员能够管理成员、检索和导入知识、分析设备历史，并通过独立确认步骤安装建议规则。

沿用 Go 服务、双 Vault、现有采集分析与确认逻辑，以及已经修复的隐私过滤和会话并发机制。所有可点击的业务操作必须接入真实接口并具有失败反馈；测试场景使用模拟服务。

本版不包含设备即时开关或调温、自然语言设备控制、房间自动分组、规则停用/撤回/任意编辑、图片上传、语音、逐 token 输出、家庭私有知识发布流水线、每成员长期记忆和会话语义搜索。已有网页聊天挂件继续保留。

## 2. 技术选择与部署

采用 Vite＋React＋TypeScript，使用 React Router 管理页面、原生 fetch 与 WebSocket 访问 Go；第一版采用普通 CSS 和共享组件，不额外引入全局状态框架。相比纯 HTML＋JS，组件和类型约束更适合多页面、多个账号及建议审核状态；Go 模板配合局部请求也是可行备选，但聊天和跨页面身份状态仍需较多客户端逻辑。

- 前端源码放在 `go-agent/web/`，构建产物放在 `go-agent/static/console/`，独立于现有挂件文件。
- 页面入口 `/app/`，前端路由以 `/app` 为 basename；生产静态文件和 API 由同一个 Go 服务提供。无需 Node 生产进程，不依赖外部 CDN、在线字体或在线图标。
- Go 只对 `/app/` 内的页面导航返回 SPA 入口；缺失资源返回 404，API 404 不得返回 HTML。
- 开发使用 Vite 代理 HTTP 与 WebSocket；显式配置控制台允许的完整 origin，保持生产鉴权强度，不通过放宽全站跨域来开发。
- 前端依赖在实施时核对官方要求、固定版本并提交锁文件。现有 Go 1.26.4 和旧挂件测试继续保留。

参考：[React 与 Vite](https://react.dev/learn/build-a-react-app-from-scratch)、[Vite 静态部署](https://vite.dev/guide/static-deploy.html)。上述目录、路由和库选择是本项目的设计决定。

## 4. 身份、登录与权限

### 4.1 账号与登录会话

账号使用稳定随机 ID，包含 username、display_name、role、disabled、password_hash、must_change_password。role 仅有 admin 和 member；首版只有项目主人是 admin，管理界面创建的账号固定为 member，不提供角色提升或管理员互相管理。

初始管理员由现有管理 Bearer 保护的 `POST /internal/console/bootstrap` 创建；仅在尚无管理员时接受，重复创建返回 409。提供命令行初始化说明，密码不得放进命令参数、日志或示例配置。管理密钥不进入前端代码或浏览器存储。初始化前，登录页显示“请由管理员完成初始化”。管理员凭据遗失可由同一管理边界下的重置接口恢复，重置必须撤销全部旧登录会话。

管理员创建成员或重置密码时发放临时密码，页面只在当次操作显示，后端不保存明文；成员第一次登录必须修改密码。完成之前仅允许 GET `/auth/me` 获取改密状态、账号标识和 CSRF token，以及 POST `/auth/password` 或 `/auth/logout`，其他业务 API 与 WS 一律拒绝。用户名限制为 3–32 位 ASCII 字母、数字、下划线和连字符，并按小写唯一；显示名支持 1–40 个 Unicode 字符。密码允许 Unicode，不截断、不做大小写或空白归一化，长度为 12–128 个字符且 UTF-8 不超过 512 字节。

密码使用现有 `golang.org/x/crypto/argon2` 的 Argon2id，随机盐不少于 16 字节，摘要 32 字节，参数 64 MiB、3 次迭代、4 线程，编码中保存算法与参数。登录执行有界限流和并发限制；账号不存在、禁用和密码错误返回统一提示。参数依据 [Go Argon2 文档](https://pkg.go.dev/golang.org/x/crypto/argon2)，需用目标机器验证成本，不复制未知哈希参数直接分配内存。

登录成功创建独立随机登录令牌，浏览器仅通过 HttpOnly、SameSite=Strict cookie 携带；服务端只保存令牌哈希。每台设备有自己的登录会话，共享同一账号 ID。登录绝对有效期 7 天，退出撤销当前登录；改密、成员禁用及重置密码撤销该账号全部登录，重新启用不会恢复旧令牌。

账号、登录会话和共享配置保存在 Vault 与静态目录之外的 `console.data_dir`。首版沿用单 Go 进程、文件持久化架构；状态修改串行、写入采用同目录临时文件与原子替换，持久化成功后才返回成功。只有账号文件确实不存在时才允许初始化；文件损坏、读取失败或已有非法数据均使控制台初始化失败，不能回退为“尚无管理员”并覆盖原数据。目录不得作为静态资源或知识库挂载。此版本不支持多个 Go 实例并发写同一账号目录。

### 4.2 请求保护

新控制台 API 使用独立鉴权域 `/api/console/v1`。旧管理 Bearer、`/internal/*` 和匿名 `agent_browser` 保持既有用途；匿名 cookie 不能获得家庭权限，控制台 cookie 不得直接访问旧 `/internal/*`。业务能力由服务端检查，前端导航隐藏只用于体验。

配置 `console.enabled`、`console.data_dir`、`console.public_origin`、`console.allow_insecure_http`。默认关闭控制台，开启时必须设置准确 origin，并配置有效的现有管理密钥；管理密钥为空、纯空白或未展开的占位符时启动报错，不开启一个无法初始化或恢复的控制台。HTTPS 模式 cookie 使用 Secure；本地开发或受信任局域网使用 HTTP 必须显式开启该选项，不能根据客户端随意发送的 X-Forwarded-Proto 降低保护。部署文档说明家庭登录的 HTTPS 配置，但本轮不替用户开放公网。

写请求校验完整 Origin 和登录会话绑定的 CSRF token；登录也校验 Origin，GET 不执行业务写入。WebSocket 校验完整 Origin、账号状态及登录有效期，不在 URL 放登录令牌。退出、禁用和到期会取消正在生成及空闲的连接；连接注册与撤销必须防竞争，每轮开始和发送最终结果前再次验证。

失败请求不自动重放 HA 写操作。退出成功会关闭连接并清空当前账号的前端数据；其他标签页收到退出事件也清空。旧请求的迟到响应不得写入另一个账号的状态。口令、回答正文和来源内容不写入 localStorage 或 Service Worker 缓存。

会话原则参考 [OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)，以上有效期、角色及产品流程为本项目约定。

## 5. 聊天与知识边界

新家庭聊天使用独立 `channel="console"`、`OwnerID="console:"+userID`，复用现有会话持久化、OwnedMessages、ListOwnedSessions、可取消处理锁和轮次切换。普通聊天固定检索 agent Vault，客户端不能提交 owner、channel 或 vault 来改变权限。匿名历史不自动归入账号。

同一账号登录手机和电脑可以恢复相同会话；不同账号猜中 SID 也返回与不存在相同的 404。控制台管理员同样走 Owned 接口，不复用旧 handler 中 Admin 可查看全局历史的分支。新的会话、切换会话和身份变更重建前端连接状态，保留已有 expectedSID 防迟到错误逻辑。保留跨连接处理锁；同一连接按收到的消息顺序处理。

聊天显示“正在生成”，完成过滤和保存后一次显示回答。网络断开后保留输入草稿，先恢复历史再决定是否需要重发，不自动重复提交不确定是否成功的消息。生成失败、容量不足和服务器错误不清除 SID；只有明确的不存在错误清除对应 SID。首版没有停止生成按钮、消息编辑、会话改名或删除。

控制台会话不进入旧全局语义索引，也不进入会话结束后的全局 personal/_memory 沉淀。会话结束仍须正常释放资源并完成状态迁移。当前旧索引没有 owner 字段，沉淀转换也不保留 owner；不能靠隐藏历史搜索按钮来代替这个隔离。后续成员长期记忆另行设计。

共享知识沿用 agent Vault 的现有公开规则，页面明确这是现有网页聊天也能使用的资料，不把它包装成“只有家人可见的私有库”。新增检索与正文接口复用严格 frontmatter 解析和 IsInternalPage；正文、索引、计数均做同样过滤，返回相对路径或不透明 ID，不暴露绝对路径。未知、无权或无效文档统一不可读取；读取失败与无搜索结果分别显示。

HA 运行资料不得经知识入口绕过设备共享规则：将配置的智能家居运行目录排除公开搜索、向量候选、实体触发扫描、正文接口和模型上下文；排除规则覆盖缓存与已有归档。新生成规则和报告同时标注 internal。实现前验证目录关系，不能把整个 agent Vault 意外作为运行目录。管理员通过专门的 HA 页面读取这些资料。管理员自行公开的普通资料继续遵循既有公开规则。

私人知识问答是管理区独立入口，复用 personal RAG 和来源结果；首版只保留当前页面内的问答，不混入 console 的共享知识聊天历史，退出后清空。文本导入仍写 personal，成功不等于公开发布；前端明确展示目标库。首版不增加从 personal 到 agent 的自动发布。

## 6. 设备、采集和自动化

### 6.1 共享与状态语义

管理员按 entity_id 选择“向家庭成员共享”，默认不共享，新发现设备不自动加入。首版统一向所有 member 共享，不增加逐成员 ACL。共享设置版本化，携带 revision 更新；过期版本返回 409，避免两个管理标签页互相覆盖。

member 设备 DTO 仅含 entity_id、name、state、unit、last_changed、last_updated；不原样返回 attributes。首页计数也只统计可见实体。管理员的设备页允许查看全部同类字段。

快照接口读取文件已有 updated_at，补充 snapshot_at、poll_interval_seconds 和 freshness。距 snapshot_at 不超过 2 倍采集间隔为 fresh，超过为 stale；不存在或时间异常为 unknown。页面标注“最近采集”“数据可能过期”，不能用 last_changed 判定设备离线，也不能用快照存在推断 HA 当前连通。

管理员采集详情区分状态快照与历史补采：记录当前进程的采集阶段、最近尝试/成功/失败时间、当前窗口批次完成数，并读取持久化 checkpoint。重启后没有记录的错误或尝试时间显示未知，不能用 checkpoint 伪造。当前状态保存成功但历史请求失败时，两部分状态独立呈现。错误输出为安全错误码和说明，移除 Token、请求头、地址及磁盘路径。

首页与设备页可见时每 30 秒请求服务器快照；隐藏标签页暂停轮询，恢复时刷新。轮询不直接发起额外 HA 采集。页面提供“刷新显示”，管理员另有“分析最近 14 天”的明确操作，分析中阻止重复点击。

### 6.2 建议流程

管理员看到 pending、superseded、applying、failed、confirmed、ignored 的真实状态。详情首先展示数据依据、时区、目标实体及结构化触发/条件/动作；未知字段或 unsupported_reason 对应不可执行提示，不能从自然语言自行拼接 HA 配置。

```text
查看建议 → 缺少有人在家条件 → 选择明确的聚合实体与状态
         → 保存绑定，打开新 ID，旧建议显示已被替代
         → 查看新版本规则 → 单独点击“确认创建自动化”
         → applying → confirmed 或 failed
```

绑定只接收现有 presence 结构，管理员负责选择真正代表“家中有人”的聚合实体，页面不能按实体名称自动猜测。时间建议继续要求该条件；关联建议保留日落后条件，动作沿用既有 light/switch/fan 白名单。

confirmed 表示 Agent 曾成功安装并归档，不表示持续监测到 HA 规则仍启用；ignored 表示忽略未执行建议，不表示关闭已安装规则。failed 显示失败说明；如果结果可能已经写入 HA，先刷新状态，再由管理员明确选择重试，同一 ID 保持现有幂等语义。历史 applying 同样不在页面加载时自动重试。

member 仅看到管理员额外勾选共享的 confirmed 结果。必须能从结构化内容完整证明所有相关实体都已共享（包括触发、动作和 presence 条件），否则整条隐藏。无法可靠解析的旧规则默认不共享。共享结果使用结构化字段生成只读摘要，省略原始错误、完整 HA payload、内部版本链和未经筛选的描述；未共享规则也不进入数量统计。

## 7. 新接口边界

以下路径均为拟新增设计，不表示现有代码已经实现。前缀为 `/api/console/v1`；业务处理直接调用现有 Go 服务，不在 Go 内部经 HTTP 转调自身，也不让浏览器持有 HA Token。

| 路径 | 权限与职责 |
|---|---|
| GET `/auth/status` | 未登录也可读，仅返回 initialized，不返回成员信息 |
| POST `/auth/login`、GET `/auth/me`、POST `/auth/logout` | 登录、身份/能力/CSRF 信息、撤销当前登录 |
| POST `/auth/password` | 修改本人密码并撤销全部旧登录 |
| GET `/sessions`、GET `/sessions/:id/messages`、WS `/chat/ws` | console channel、本账号历史与普通聊天 |
| GET `/home` | 当前角色可见的首页摘要 |
| GET `/devices` | 按权限裁剪设备、快照元信息 |
| GET `/suggestions` | admin 全状态，member 已授权确认结果 |
| GET `/knowledge/search?q=`、GET `/knowledge/page?path=` | 仅 agent 公开资料，包含正文授权与路径校验 |
| GET/PUT `/admin/sharing` | 共享实体和确认结果白名单、revision 冲突检查 |
| GET/POST `/admin/members` | 成员列表、创建 member 与临时密码 |
| PATCH `/admin/members/:id`、POST `/admin/members/:id/reset-password` | 修改显示名/禁用状态、重置成员密码；拒绝修改 admin |
| GET `/admin/collection`、POST `/admin/analyze` | 采集可观测状态、复用现有分析 |
| POST `/admin/suggestions/:id/bindings`、`/confirm`、`/ignore` | 复用已有不可变建议与确认状态机 |
| GET `/admin/vault/status`、GET `/admin/vault/search` | 适配已有知识接口，去除绝对路径 |
| POST `/admin/wiki/ingest`、POST `/admin/knowledge/query` | personal 导入和问答，复用现有处理流程 |

初始化与管理员恢复放在旧管理 Bearer 域的 `/internal/console/bootstrap`、`/internal/console/reset-admin`，不对家庭 cookie 开放。

新 HTTP API 使用小写 snake_case DTO、数组返回 []，时间使用带时区的 RFC3339。错误采用 `{error:{code,message,request_id}}`，不混用现有旧接口大小写字段。鉴权失败 401、权限不足 403、无权或不存在对象 404、版本/状态冲突 409、可修正条件错误 422、限流 429、上游失败 502、能力未配置 503。CSRF 不通过返回 403。

新增适配层复用业务服务，不复制采集、分析、确认、RAG 或会话锁实现。旧 API 契约继续有回归测试。

## 8. 交互与异常验收

- 登录过期返回登录页，清空已取到的私人内容；正在编辑的普通输入不跨账号恢复。403 不伪装成空列表。
- 区分“未配置家庭设备”“等待首次采集”“暂无向你共享的设备”；陈旧数据保留上次数据并标时间，服务请求失败显示错误和重试。
- 区分“暂无建议”“数据不足以形成建议”和“分析失败”；只有后端提供不足依据时才显示数据不足。
- 绑定后的新 ID、迟到 404、跨账号迟到响应均有行为测试。409 重新取当前版本；422 保留当前表单并定位可修改字段。
- 私人来源与共享来源清楚区分。Markdown 关闭原始 HTML，限制链接协议，默认不加载远程图片；文档路径不能穿越或借符号链接读取根目录外文件。
- 键盘可完成登录、发送、对话框确认和退出；输入有标签，焦点可见，错误不只靠颜色；中文输入法组合期间按 Enter 不发送。
- 在 390px 手机宽度和 1440px 桌面宽度检查主要页面，无全页横向溢出；长设备名、长正文和代码块有明确换行或局部滚动。

## 9. 实施拆分与完成标准

正式实施计划在本设计审阅后编写，按以下可独立验收的交付顺序展开：

1. 账号持久化、初始化、登录与撤销；包含真实 HTTP 权限测试。
2. console 会话归属、WS 撤销、索引与沉淀隔离；保留原并发和恢复回归。
3. 家庭只读与管理员 API 适配、共享策略、知识运行资料排除、采集可观测字段。
4. 前端构建、导航、登录、普通聊天与跨设备历史；手机和桌面布局。
5. 设备、建议绑定确认、知识与成员管理页面，接通真实模拟后端。
6. 端到端测试、Go 全套测试/vet/build、前端类型/行为/build 检查、旧 Node/Python 回归、Linux race、启动与初始化文档。

关键验收必须包含两个 member 和一个 admin：跨账号猜 SID、管理员普通聊天仍限本人、成员不能读取 personal、成员不能获取未共享实体或建议、公开 RAG 不能读取 HA 运行归档、console 聊天不写全局索引/沉淀、改密/禁用时空闲和生成中 WS 及时撤销、进程重启后正常登录与历史恢复。初始化验收还包括缺管理密钥拒绝启动、损坏账号文件不触发新建管理员、并发 bootstrap 只有一次成功，以及强制改密账号可获取 CSRF 并完成改密但不能访问业务 API。

自动化验收从分析产出的真实结构开始，经 UI 补条件、打开新版本、人工确认，到模拟 HA 写入和归档；双击、刷新及错误重试不得造成错误版本安装或额外操作。组件测试之外至少一组浏览器测试使用 Go fixture 服务，不能仅靠拦截前端请求宣称后端已集成。

本轮设计没有安装依赖、编写产品代码或操作真实设备。后续实现可先通过离线 fixture 交付可运行页面；真实 HA 安装、设备动作、断 WAN 与现场恢复继续列为需要现场验收的项目。

## 10. 代码依据与设计复核

核对依据为当前修复工作区的：

- `go-agent/internal/gateway/browser_auth.go`：匿名 cookie 与管理 Bearer 边界。
- `go-agent/internal/gateway/http.go`：现有路由、admin 历史分支、固定 personal REST、知识与 HA 接口。
- `go-agent/internal/gateway/websocket.go`：固定 agent Vault、消息缓冲、会话锁、异步索引及连接生命周期。
- `go-agent/internal/core/session_owner.go`：可复用的会话归属检查。
- `go-agent/internal/core/session_store.go`、`agent.go`：全局语义索引和会话沉淀的现有限制。
- `go-agent/internal/vault/reader.go`、`page_filter.go`、`embedding.go`：解析、可见性和缓存边界。
- `go-agent/internal/smarthome/store.go`、`collector.go`：快照时间、分阶段采集和 checkpoint。
- `go-agent/internal/smarthome/suggestion_bindings.go`、`manager_actions.go`、`automation.go`：绑定新版本、人工确认和运行归档。

已进行账号与页面两个方向的独立只读核对；本设计明确纳入发现的控制台索引/沉淀隔离、WebSocket 撤销及 HA 归档绕过共享边界问题。书面设计复核后补齐了启用控制台的管理密钥前提、损坏账号文件的拒绝策略，以及强制改密时获取 CSRF 的允许路径。现有普通 RAG 跳过 `_memory`，不将未来归属风险误报为已经验证的成员间自动串读。
